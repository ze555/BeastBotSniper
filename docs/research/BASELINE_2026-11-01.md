## Code integration observations
- `apexPredator.ts` imports `reasoningEngine.ts` and `researchLogger.ts`, but does not import `exitEvidenceEngine.ts` or `directionStateEngine.ts`. Their tests do not prove that either engine governs production decisions.
- `exitEvidenceEngine.ts` declared `maxScore: 9` in its decision interface but returned `maxScore: 8`, despite nine possible score points. This branch corrects the returned ceiling and adds a regression assertion.
- `fetchLiq()` in `apexPredator.ts` returns fixed mock values, not measured liquidation data.
- `fetchOI()` returns an empty array on failure. Downstream logic must preserve an explicit unavailable state rather than interpret missing OI as zero change.

## Implemented research branch components
- `src/lib/strategyPortfolioEngine.ts` now evaluates four independent candidate families on completed OHLCV candles: trend continuation, breakout/retest, liquidity sweep/reclaim, and momentum expansion. Flow is explicitly a taker-buy/close-location proxy; it is not institutional orderflow.
- Candidate selection is per side and selects the highest-scoring accepted setup. A BTC regime conflict applies a score penalty, not a blanket direction ban.
- The independent risk guardian defaults to 0.5% equity risk per trade, 2% aggregate open risk, 2% daily loss limit, five concurrent positions, and a same-direction concentration proxy of two positions. These are research defaults, not validated optima.
- `apexPredator.ts` has an optional strategy portfolio path behind `strategyPortfolioEnabled=false` by default. It evaluates closed 15m candles, obtains a fresh ticker price before entry, validates the live stop distance, and uses the guardian's risk amount. It is not enabled in the branch's default configuration.
- OI availability is now explicit in the whale reader. The fixed liquidation-map mock has been replaced with an explicit unavailable result; the system must not label synthetic values as observed liquidity.
- `simulatePartialExitTrade` models recorded position size, initial stop reconstructed from TP1/TP1-R, entry/exit taker fees, slippage, +0.45R/-0.25R soft protection, strategy-specific target levels and partial allocations, stop progression, and conservative intrabar collision treatment. It excludes incomplete 1m candles at the recorded exit boundary.
- `strategyPortfolioReplay.ts` reports candidate acceptance on historical pre-entry snapshots and fill-aware exit diagnostics. It intentionally does not claim strategy expectancy because the source data only contains executed trades.
